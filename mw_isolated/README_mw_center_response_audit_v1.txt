MW 中心响应只读审计 v1 — 2026-10-16

为什么检查
==========
trial11 从 trial10 仅增加 LMC 初始 x 0.5 kpc，实际终点 LMC 相对 MW 的 x 改变 -0.146955 kpc。
同一比较中 MW BH 的 x 改变 +0.133400 kpc，LMC 盒坐标 x 只改变 -0.013555 kpc。
这是坐标分解，不证明 BH 抖动或数值错误。可能包含真实 MW 响应，也可能涉及 BH 相对恒星中心的位移。
已有验证器有 BH 时直接用 BH 位置，无法凭现有审计 JSON 区分这两部分。

本脚本做什么
============
读取同一历史 JSON 指向的 trial10/11 合并 IC 与各自目标快照。
核对 IC 文件实际 SHA256、单位、源快照指纹、模型、测量定义、目标时间及已记录的坐标速度。
以合并 IC 的 MergeParticleOrigins/PartType4==0 冻结“插入时已存在的 MW 恒星”完整身份。
该样本包含 MW 弛豫阶段形成的恒星，但排除插入后新生成的恒星；不是只按父 ID 粗略匹配。
分别以 2、5、10 kpc 核心孔径求独立 MW 恒星中心，计算 BH−恒星中心偏移及两轮差分。
同时保留现有验证器的 BH 位置/内区恒星速度定义，重新核对卫星恒星中心和原记录。
只输出诊断 JSON；不改 IC、快照、原残差 CSV、shooting 候选、观测目标、容差或任何 GIZMO 参数。
不启动 GIZMO，不绘制流体图，不需要 yt。

运行
====
把压缩包放到原工作目录，执行：

cd ~/gizmo-runs/mw_isolated
unzip -n mw_center_response_audit_v1.zip
python audit_mw_center_response_v1.py \
  --history-json ./shooting_response_audit_04_11.json \
  --trials trial10 trial11 \
  --output ./mw_center_response_10_11.json

依赖 numpy、h5py（原模拟分析环境已使用）。
输入路径取自历史 JSON，适用于原机器原目录；如果移动过文件，脚本会明确报缺少文件，不能跳过指纹检查。
默认只读这两轮的目标快照，不扫描整个输出目录。请把 mw_center_response_10_11.json 提供回来。
同名输出已存在会停止，选择新输出文件名即可。

如何解释
========
如果 BH 与不同孔径恒星中心在两轮中共同平移，而 BH−恒星中心偏移变化很小，说明此次参考原点变化主要与恒星中心共同运动。
如果 BH−恒星中心偏移变化占主要部分，需要进一步检查 BH 轨迹/重定位和中心定义的适用性；单凭两个终点仍不能认定是数值抖动。
如果不同孔径给出的中心变化差异大，则先考虑盘/核球形态、偏心和估计方法的孔径敏感性。
2/5/10 kpc 对比不是误差条。不能挑选让残差通过的孔径，也不能直接扣除 BH 位移或事后放宽3σ。
两轮并非相同初态的重复运行，本脚本不能估计随机反馈或并行数值计算的可重复性。

检查边界
========
对现有验证器的复现采用其原来的坐标约定，然后按历史中记录的单位换算展示物理诊断。
当前长度单位极接近1 kpc，这个区别不是本次约0.1 kpc中心响应的解释。
脚本适用于当前非宇宙学、非周期、单 HDF5 文件快照，要求完整身份字段和显式旧恒星范围元数据。
这次审计用于决定下一步应修正测量定义还是继续测量动力学响应，不预先判定任何一个原因。
